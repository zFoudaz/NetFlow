# NetFlow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build NetFlow, an elevated Windows 10/11 Tauri v2 desktop application with a React Flow drag-and-drop canvas that routes individual Windows apps and chained user-launched VPNs (Karing, Cloudflare WARP, OpenVPN) across multiple physical network interfaces simultaneously via a bundled `sing-box` + `Wintun` L3 TUN engine.

**Architecture:** The Rust backend is split into a Tauri-agnostic `crates/netflow-core` library (discovery, DAG validator, `sing-box` v1.14+ config compiler, workflow storage, atomic crash recovery, Win32 route/proxy management, VPN adapters, sidecar supervisor, Clash API live traffic client) and a thin `src-tauri` shell (IPC commands, system tray, startup crash recovery). The React + TypeScript frontend (`src/`) renders the sketch-faithful left palette, React Flow canvas (`Interface -> VPN -> ... -> Connected Apps`), named workflow switcher with hot-swap Apply, and a live traffic log drawer.

**Tech Stack:** Rust (Cargo workspace, `windows` crate Win32 APIs, `tokio`, `serde`, `tokio-tungstenite`), Tauri v2, React 19 + TypeScript + Vite, `@xyflow/react` (React Flow), Zustand, Vitest + Testing Library, bundled `sing-box` v1.14.4 + Microsoft-signed `wintun.dll` 0.14.1.

**Spec:** [2026-11-24-netflow-design.md](file:///d:/Study_2/Projects/NetFlow/docs/superpowers/specs/2026-11-24-netflow-design.md)

## Global Constraints

- Platform: Windows 10 / 11 (x64) only; app manifest MUST request `requireAdministrator`.
- Zero unsigned kernel drivers: only Microsoft-signed `wintun.dll` + official `sing-box.exe` sidecar; never require Test Signing Mode or disabling Secure Boot.
- External VPN model: user launches Karing, Cloudflare WARP, and OpenVPN externally; max 1 node per VPN provider on canvas in v1; VPN chaining (`Interface -> VPN 1 -> VPN 2 -> Apps`) allowed as a cycle-free DAG tracing back to a physical Interface.
- Zero silent leaks: `NetFlow-TUN` uses FakeIP (`198.18.0.0/15`) + protocol/SNI sniffing, blocks IPv6 (`ip_version: 6 -> reject` + suppress `AAAA`), disables Windows System Proxy while active (restored on Stop/crash), and fails closed on VPN or physical interface drop.
- Atomic safety: `%APPDATA%\NetFlow\recovery.json` MUST be written and flushed before any route, metric, System Proxy, or WARP mode mutation, and restored on Stop, fatal `sing-box` exit, app exit, or next startup after crash.
- v2 auto-start readiness: `crates/netflow-core` MUST have zero dependency on `tauri` crates.
- All compiled `sing-box` configs MUST validate with `sing-box.exe check`.

## Review Focus

1. **Case-variant and whitespace executable names (`Chrome.EXE`, `" chrome.exe "`)** — duplicate detection and `sing-box` rules must normalize names (trim + case-insensitive uniqueness + canonical `.exe` matching) so duplicate or malformed entries never slip through. *(Pinned in Task 2 & Task 3)*
2. **Partial Apply failure and crash-recovery rollback** — if `Apply` fails mid-way (e.g., Karing routes already neutralized, then `sing-box` exits or WARP fails), NetFlow must immediately roll back every already-applied mutation from `recovery.json` instead of leaving Windows networking broken. *(Pinned in Task 5 & Task 8)*
3. **Saved workflow referencing disconnected/missing interfaces or stopped VPNs** — loading a saved workflow whose interface (`Ethernet`) is unplugged or whose VPN is stopped must render cleanly on the canvas with offline badges and fail pre-flight validation with an actionable error before mutating any route. *(Pinned in Task 4 & Task 8)*
4. **Hot-switching active workflows without clobbering baseline recovery** — switching from Workflow A (`Karing + OpenVPN`) to Workflow B (`Karing + WARP`) while active must restore OpenVPN's original routes, preserve Karing's original pre-NetFlow baseline routes (never overwriting baseline with metric-500 routes), neutralize WARP, and cleanly restart `sing-box`. *(Pinned in Task 8)*
5. **Dirty-state guard and active-workflow deletion in Workflow Switcher** — switching workflows with unsaved edits must prompt or keep edits safe, and deleting the currently active workflow must require stopping or fall back cleanly without corrupting UI state. *(Pinned in Task 10)*

## File Structure

- `Cargo.toml` — Cargo workspace linking `crates/netflow-core` and `src-tauri`.
- `scripts/fetch-sidecars.ps1` — Downloads pinned `sing-box` v1.14.4 (`windows-amd64`) and `wintun.dll` 0.14.1 (`amd64`) into `src-tauri/binaries/` and `src-tauri/resources/`.
- `crates/netflow-core/src/model.rs` — All serializable domain types (`WorkflowGraph`, nodes, edges, VPN settings, discovery snapshots, runtime states, saved workflows).
- `crates/netflow-core/src/validator.rs` — Pure graph topology validator (DAG, edge rules, WARP Proxy downstream restriction, unique normalized app names, max 1 Default, max 1 per VPN provider).
- `crates/netflow-core/src/compiler.rs` — Pure `sing-box` v1.14+ JSON compiler (dual-stack TUN, FakeIP, IPv6 reject, topological VPN chain rules, OpenVPN DCO `/32`, Connected Apps rules, Default `final`, Clash API).
- `crates/netflow-core/src/storage.rs` — Atomic JSON CRUD for named workflows in `%APPDATA%\NetFlow\workflows\`.
- `crates/netflow-core/src/recovery.rs` — Atomic snapshot persistence and stale crash-recovery detection for `%APPDATA%\NetFlow\recovery.json`.
- `crates/netflow-core/src/discovery.rs` — `SystemDiscovery` trait + Win32 implementation enumerating physical IPv4 adapters, running processes, and live Karing/WARP/OpenVPN state (ports, adapters, DCO remote server IP).
- `crates/netflow-core/src/win_net.rs` — `WindowsNetworkOps` trait + Win32 implementation for IPv4/IPv6 route CRUD, interface metric updates, `/32` host routes, HKCU System Proxy + `WinINet` refresh, and `warp-cli` invocation.
- `crates/netflow-core/src/vpn_adapters.rs` — Per-provider pre-flight, route/mode neutralization, and restoration logic for Karing, Cloudflare WARP (TUN primary + Proxy fallback), and OpenVPN (Wintun/TAP/DCO).
- `crates/netflow-core/src/runtime.rs` — `EngineRuntime` orchestrator: Apply, Hot-Switch, Stop, Crash Recovery, `sing-box` process supervisor, `NetFlow-TUN` route-priority verification, and 2-second fail-closed health watcher.
- `crates/netflow-core/src/traffic.rs` — Local Clash API WebSocket client emitting ring-buffered `LiveConnection` snapshots mapped to NetFlow node IDs.
- `src-tauri/src/{main.rs,lib.rs,commands.rs}` + `src-tauri/{tauri.conf.json,build.rs,app.manifest}` — Elevated Tauri v2 shell, IPC commands, event emitters, startup crash recovery, and system tray.
- `src/{types/workflow.ts,lib/tauri.ts,store/useNetFlowStore.ts}` — Frontend types, typed Tauri IPC client, and Zustand state store.
- `src/components/{TopBar.tsx,Sidebar.tsx,FlowCanvas.tsx,AddAppModal.tsx,LiveTrafficDrawer.tsx}` + `src/components/nodes/{InterfaceNode.tsx,VpnNode.tsx,AppsNode.tsx}` — Sketch-faithful visual workflow UI.
